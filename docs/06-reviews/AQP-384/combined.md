## Security checks (the brief's focus list)

| # | Check | Result |
|---|---|---|
| 1 | **Nonce: CSPRNG, per request, never reused or cached** | **Verified.** `crypto.getRandomValues(new Uint8Array(16))` (Web Crypto, a CSPRNG) gives 128 bits of base64, which the CSP `base64-value` grammar accepts (`csp.ts:37-39`). One nonce per proxy call (`proxy.ts:91`), held in no module state. The unit test checks 50 distinct values of at least 16 bytes, and the E2E test checks a second request on the production build. Pages that carry a nonce are not stored: signed-in pages get `private, no-store` from the proxy (and the E2E asserts it on `/queue`); the reset pages get it from `next.config.ts`; `/sign-in` is dynamic, so Next sends its own `no-store` value. A restore from the back-forward cache brings back the document with its own header, so the nonce still matches |
| 2 | **No `'unsafe-*'` in production** | **Verified.** `script-src 'self' 'nonce-…' 'strict-dynamic' 'sha256-…'`, and `style-src 'self' 'nonce-…'`. The relaxations (`'unsafe-eval'`, `style-src 'unsafe-inline'`, `ws:`/`wss:`) apply only when `process.env.NODE_ENV === 'development'`, an exact match (`proxy.ts:92`). Next inlines that value at build time, so `next build` and `next start` always get `'production'`, and vitest gets `'test'`. The E2E checks `script-src` on the production build. The wiring itself has no test (SQR-03) |
| 3 | **`style-src-attr 'unsafe-inline'`** | **Accepted.** Radix and floating-ui write `style=""` attributes, which a nonce cannot cover. An attribute cannot run script or load anything, because `img-src`, `font-src` and `default-src` still limit `url()`. DEF-054 and STD-F-01 name the same loosening |
| 4 | **`img-src 'self' blob:`; `connect-src 'self'`; `frame-src 'none'`; `form-action 'self'`; `base-uri 'self'`; `object-src 'none'`** | **Verified against the code.** Only the portal's own scripts can mint a `blob:` URL (for picture previews). There is no external `fetch`, no `<iframe>` and no worker in `src`. Sign-in and sign-out post with `fetch`, so the redirect behaviour of `form-action` is not involved. `base-uri 'none'` would be one step stricter (SQR-07) |
| 5 | **`'strict-dynamic'`** | **Accepted, consequences understood.** CSP3 browsers ignore `'self'` for scripts and trust any script that a nonced script creates with DOM APIs. That is what lets the lazy dialog chunks and the first-open loader load. A parser-inserted script (stored XSS through markup) has no nonce and is stopped. The cost: a DOM sink such as `script.src = <attacker value>` would be trusted. No such sink exists in `src`, and React escapes text. The hash of the early-tap script still works under `'strict-dynamic'` |
| 6 | **The `__webpack_nonce__` script** | **Sound as used, but it trusts its input** (SQR-02). The script carries the nonce itself (`layout.tsx:37`), and an injected script that already runs could read the nonce from `document.scripts`, so exposing it to JavaScript adds no new risk. But the layout writes the `x-nonce` request header into an inline script with `JSON.stringify`, which does not escape `<`. That is safe only while the proxy has replaced the header, and two page paths render without the proxy |
| 7 | **Header coverage per answer type** | **Pages, errors, redirects, JSON, static files: verified** by unit tests (9 answer types) and the E2E test (pages, 404, 307, 401 and 200 JSON, a `/_next/static` script). **The picture download: regressed** (SQR-01). Next drops a route's header when the proxy already set the same name, so `/api/v1/images/[id]` now sends the proxy's `default-src 'none'; frame-ancestors 'none'` instead of its own `default-src 'none'; sandbox`. **The export download** gets the API policy and `nosniff`; it is an `attachment`, so losing `sandbox` there does not matter. **The `/_next/image` route** gets nothing from the app, but the Next image optimiser sets `nosniff` and its own CSP. **The `/_next/staticX` and `/_next/imageX` 404 pages** get no headers at all (SQR-02) |
| 8 | **Request-header spoofing; auth bypass; return path** | **No bypass.** `isPublicPath` uses exactly the old matcher's pattern (anchored, with a `/` or end-of-path boundary), and the unit tests pin both sides. The proxy is still not an authorisation control: `requireUser()` reads the database. The path is normalised before matching (`/sign-in/../queue` becomes `/queue`). **Better than before:** `x-return-path` and `x-session-cookie` used to reach `/sign-in`, the reset pages and `/api/auth/*` unfiltered, because the proxy did not run there. Now they are deleted on public paths and set by the proxy elsewhere. `x-nonce` is replaced on page paths and deleted on API paths. A browser's `Content-Security-Policy` request header is overwritten on pages (tested). On API paths, Next copies the proxy's response policy over it. `x-middleware-override-headers` from a client is removed by Next's internal-header filter. The reset token is still never copied into the return-path header (AQP-354 check 14 holds) |
| 9 | **Public pages still work** | **Verified.** Sign-in, `/forgot-password` and `/reset-password` return 200 with or without a cookie (unit test), hydrate under the policy with no violation, and cannot be framed (E2E at 3 widths). The full E2E suite of about 2,100 tests, which signs in throughout, is green with the CSP on |
| 10 | **Dynamic rendering and `Cache-Control`** | **Verified.** The root layout reads `headers()`, so every route is dynamic, and `next build` lists them so. No route uses `force-static`, `revalidate`, `generateStaticParams` or `'use cache'`. JS budget: `/queue` is 190.2 KB of 200 KB. The proxy still sets `no-store` on every non-public answer. A route cannot override it, but routes already send the same value |
| 11 | **Alignment with the architect's split** | **Aligned on what matters:** CSP, `nosniff`, `Referrer-Policy` (`same-origin`, and `no-referrer` on the two reset pages) and `Permissions-Policy` from the app; **no HSTS from the app**, and a unit test pins that even with an https `APP_ORIGIN`. **Deviations judged acceptable** (SQR-05): `X-Frame-Options: DENY` kept, a wider `Permissions-Policy`, every page dynamic, and the dev relaxations. §8's "every response" in practice means pages and API answers; static files get the three headers that apply to a file. That is reasonable |
| 12 | **Test adequacy** | **Good, with gaps.** Removing any header, or weakening `frame-ancestors`, `script-src`, `img-src`, `connect-src`, `object-src`, `base-uri` or `form-action`, fails a unit test. Removing the nonce from the layout fails the E2E test (the nonce check and the scroll-lock style). A changed early-tap script changes the hash, and a source scan pins the exact rendered text. The E2E violation recorder has a working control. **Gaps:** no test of the picture download's policy as it reaches the wire (it would have caught SQR-01; the unit test calls the handler and skips the proxy), and no test of the proxy's `NODE_ENV` switch (SQR-03) |
