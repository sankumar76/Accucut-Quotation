## Summary

The JEA wrapper is removed, not left half there. Nothing in the install, the module, the package or the workflow creates a group, an endpoint, a grant, a service entry, a shortcut or a `jea` folder. Stage 13 checks for each of these after the install, after both updates and after the rollback. The restore's controls are unchanged (F4). The only edits on the restore path are the "Restore run by" line, the event ending and the SQR-04 guard. All three are covered by tests that fail without the change. I confirmed that myself against `master`'s module and install script. The README path is correct and complete. The findings are about test strength and a latent encoding trap in a shared helper. None of them is a risk to the release.

## Findings

| ID | Severity | File:line | Issue | Fix |
|---|---|---|---|---|
| QLT-681-01 | Minor | `deploy/windows/tests/install.Tests.ps1:898` | **The exit-code assertion of the binding test can never fail.** `Start-Process -PassThru` without `-Wait` does not keep the process handle. In Windows PowerShell 5.1, `$process.ExitCode` is `$null` after `WaitForExit(ms)`, and I reproduced this with a child that runs `exit 7`. So `$process.ExitCode \| Should -Not -Be 0` passes whatever the child returned. The test still proves the behaviour through the "parameter cannot be found" text, so nothing is unproven today. But the line claims a check it does not make | Keep the handle before the child can exit: `$process = Start-Process ... -PassThru; $null = $process.Handle`. Then assert `$process.ExitCode \| Should -Not -BeNullOrEmpty` and `\| Should -Not -Be 0`. **Test that catches it:** the same test, which then fails if the child exits 0 |
| QLT-681-02 | Minor | `deploy/windows/AccucutOps.psm1:2625` | **A test seam in an exported function runs any scriptblock it is given.** `Get-AccucutRunningAccount -Source` exists only so that Pester can make the identity call throw. It is invoked with `.Invoke()` because the trust-block test forbids the call operator in the module. This is not a privilege problem: whoever calls it already runs code in the same elevated session. But it gives the release an exported parameter that runs arbitrary code, and it steps around the purpose of the "no load site" rule. It also departs from the pattern the same PR uses for `Write-AccucutApplicationEvent`: a small internal function that Pester mocks | Move the .NET call into an internal function, for example `function Get-AccucutWindowsIdentityName { [System.Security.Principal.WindowsIdentity]::GetCurrent().Name }`. Leave it out of the export list. Call it from `Get-AccucutRunningAccount` and remove `-Source`. In Pester: `Mock Get-AccucutWindowsIdentityName -ModuleName AccucutOps { throw 'no identity' }`. **Test:** the existing "returns unknown account when the identity call throws" case, rewritten with the mock |
| QLT-681-03 | Minor | `deploy/windows/AccucutOps.psm1:401-404` | **With the guard on, text on standard input is encoded in code page 437.** The BOM disappears because .NET Framework's `Process.Start` builds the standard-input writer from `[Console]::InputEncoding`, and the guard sets that to 437 when the console encoding has a preamble. The SQR-04 test passing shows this. So `$process.StandardInput.Write($StdIn)` writes CP437, and a character outside it (for example `₹`) becomes `?`. **No caller is affected today.** The SQL is static, the database names are checked against an ASCII pattern, and the `job_runs` result goes through `-v` on the command line. In a default OEM console this was already the case before the PR. But `Invoke-AccucutNative` is the shared helper, and its help says that "a secret goes in -Environment or -StdIn". A later non-ASCII secret or SQL would be changed silently. I worked this out from the .NET Framework behaviour that SQR-04 depends on. I could not run a probe, because the shell permission was refused | Make the contract explicit, in one line, before the start: `if ($PSBoundParameters.ContainsKey('StdIn') -and $StdIn -match '[^\x00-\x7F]') { throw 'Invoke-AccucutNative -StdIn takes ASCII text only.' }`. Add a sentence to the help. If non-ASCII is ever needed, write UTF-8 bytes to `StandardInput.BaseStream`, as the key and dump pipes do. **Test:** a Pester case that a non-ASCII `-StdIn` is refused before any process starts |
| QLT-681-04 | Info | `deploy/windows/AccucutOps.psm1:2661-2664` | **The cut before " Run by" (the developer's point 2) is accepted.** The spec (S3.1 b) says to add the ending "before the redaction and the cap". The code redacts both parts, then shortens the message so that message plus ending fit 1,000 characters. For a short message the result is identical. For a long one it is better: the account is never cut off. A redaction placeholder can be shortened, but a secret cannot be exposed, because redaction runs first. `[Math]::Max(0, ...)` covers an absurdly long account name | None. The architect can bring S3.1 (b) into line with the code in a later records pass (Issues for other roles) |
| QLT-681-05 | Info | `tests/unit/windows-deploy-files.test.ts:981` | **This ordering check is vacuous.** `functionBody` keeps the lines inside `<# ... #>` (`code()` drops only lines that start with `#`). The behaviour is proved by the Pester case "cuts a long message before the ending" (1,000 characters, ends with the account), so nothing is unproven | Assert the code line instead: `expect(event).toContain('if ($text.Length + $tail.Length -gt 1000)')`, or drop the line |

The likelihood is about the same as before: the IT person already ran restores as an administrator, and now the Admin does too. The sentence "one at a time" is a mitigation, not a control, and the safety copies keep the outcome recoverable | Keep SQR-03 open as Minor on #516 for the hardening window. ## The developer's six points

1. **The restore path is unchanged except for the three named edits.** Confirmed. See F4 above.
2. **The cut before the ending.** Accepted as better than the spec (QLT-681-04).
3. **The `-Source` seam and SQR-03.** The seam is safe but should become an internal mocked function (QLT-681-02). SQR-03 stays Minor on #516 (QLT-681-06).
4. **`Add-AccucutFileReadAccess` removed.** Right call: no function that widens an ACL ships in the release. Its only other caller was the R2 test, which now has its own helper with the same code (`Add-TestFileReadAccess`), so R2 still proves the same rules.
5. **Tests beyond the spec.** Both are good additions. QLT-681-01 is about one assertion line.
6. **Workflow diagnostics removed.** Correct. They read the endpoint's state, which no longer exists. The `restore.log` and event lines are kept.

## Security checks asked for

- **Nothing privileged half-removed.** Confirmed in code and on a real install. No `New-LocalGroup`, `Register-PSSessionConfiguration`, `sdset`, `WScript.Shell` or `CreateShortcut` is left in `install.ps1` or the module (Pester (c), Vitest). Stage 13 finds no group, WSMan plugin key, session configuration, shortcut or `jea` folder, and no `S-1-5-21-` SID in either service's DACL.

Stage 13 asserts exactly two entries, protected and owned by Administrators. A new Pester case asserts the same on a fresh file. The R2 reader check is unchanged.
- **The event ending** goes through `Hide-AccucutSecrets` and the control-character filter like the message. An account name is not a secret.
