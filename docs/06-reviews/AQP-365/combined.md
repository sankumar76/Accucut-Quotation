| 1 | **Which customer values change in the save** (AC-1, AC-2, AC-6) | **Correct.** `moveCustomersToDefault` runs one `UPDATE customer_rates ... FROM customers c WHERE c.deleted_at IS NULL AND cr.process_item_id = $id AND cr.value = $previous::numeric`. Both columns are `DECIMAL(18,4)`, so the comparison is exact numeric equality and never a JavaScript number. It runs only when `changesFrom` kept a new `defaultValue`, so a name-only, unit-only or other-spelling save moves nothing (AC-6 block: name, unit, same default, other spelling). ## Verdict

**APPROVE WITH COMMENTS.** There is no Blocker or Critical finding, so the §9 item 2 merge condition is met.

- **Exactly the right values change.** In the save, only non-deleted customers holding exactly OLD move to NEW. In Save choices, only customers chosen Apply whose value is still the one shown move. A deleted customer, a customer with its own value, a kept or skipped customer, and every approved estimate, its stored values and its export stay as they were.
- **Concurrency is safe.** The guard and the write are one statement under the shared table lock. Concurrent saves serialise, a second Save choices skips, and a changed default answers 409 with nothing changed.
- **The audit is complete and atomic.** It writes one entry per changed customer after the rate's own entry, with one request ID, in the same transaction, and rolls back with the change.
- **Access and confidentiality hold.** The route is Admin only, checked before the ID is read, with a strict body and the 1,000 cap. The new answer fields reach only Admin routes.
- **Must be fixed before merge:** none.
- **Major, to resolve before G8:** SQR-01. The solution-architect rules on `recordMany`, or the product-manager records the NFR-010 exception. Open a `tech-debt` issue for the hardening window if it is not done here.
- **Optional before the squash (a few lines each):** SQR-02, SQR-03 and SQR-04. Otherwise they go to the hardening window.
- **Follow-ups:** SQR-05 goes with the NFR-011 revisit. SQR-06 goes to the solution-architect and SQR-07 to the ux-expert.
