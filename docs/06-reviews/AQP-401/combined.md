## Summary
The security design is sound and follows architecture section 4.12 c and 7C's pattern. Both new routes are Lead/Admin only in the route manifest, so `withRoute` refuses an Engineer 403 before the params are read; the service checks the role again (`assertMayMarkQuoted`) before it reads anything. The remarks are judged by the one shared rule (`checkIgnoreRemarks` over `validateTextInput`, 500 code points, DL-219 hidden characters), in the dialog and in the service, before the transaction. The write is one transaction under the estimate's `FOR UPDATE` lock: the state machine decides `IGNORE` / `RESTORE`, a conditional `UPDATE` writes or clears the three columns, and the `estimate.ignored` / `estimate.restored` entry is written in the same transaction (a failed entry rolls the layer back; tested at unit and integration level). The answers are strict schemas with no ID and no figure.

The freeze (AC-6, DL-304, A-CR01-8) is enforced route by route. The routes that did not ask the state machine (export summary and file, Remove price, Cancel approval, reassign) now have their own check under the lock or the snapshot. `tests/security/ignored-estimate-refusals.test.ts` builds its list from the route manifest, not from a list of its own, and its 49 cases ran green on e03225bf. I checked the manifest by hand: it enumerates **every** implemented state-changing route under `/api/v1/estimates/[id]/` and `/api/v1/tasks/[id]` (18 calls, including `tree/move` as 3D left it, the image PUT/DELETE, Cancel approval, Remove price, Change customer, reassign, Calculate, Recalculate, Approve, Unlock, Mark as quoted, the saves and both export reads). For an Engineer the order is 404 for a task that is not theirs before 409 (`mayOpen` runs before `assertEditable` in `lockForChange` and `applyTransition`), pinned in `estimate-service.test.ts` and the integration test. The Engineer's `ignored` object and the queue's `ignoredRemarks` carry a time, a name and the Lead's words, and no ID or figure; the canary scan over an Engineer's reads of an ignored estimate finds nothing.

No Blocker, Critical or Major. Three Minor findings, all on the client and none with a data effect: the read-only drop-down swallows browser shortcuts (QLT-01); a picture change refused while ignored shows "Restore it first" to the Engineer instead of the alert (QLT-02); and the page-level announcer keeps its last sentence in the DOM indefinitely (QLT-03). The first-load deltas on master 02460fbe are **`/queue` +855 B** (under the 1,500 B budget) and **`/estimates/[code]` +737 B**, plus an unstated **`/assign` +130 B**; all accepted (QLT-07).
