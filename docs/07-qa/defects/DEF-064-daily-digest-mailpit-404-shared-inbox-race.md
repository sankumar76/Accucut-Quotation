## Fix route (developer; test-only; binding form: DL-325 (F), which adds to DL-305 (5))
**Invariant:** a test's read of the inbox can never lose a message that another file, or Mailpit itself, removes while it reads.
1. **No whole-inbox delete.** The three `capture.clear()` calls (`outbox-send.test.ts:108`, `alerts-settings.test.ts:77`, `assign-email.test.ts:118`, `git grep` on `master`) go; `clear()` either goes or is no longer called.
2. **Deleting a file's own messages by ID still breaks another file's `list()`**, which GETs every message. So one of: nothing is deleted; or `list()` reads only the file's own messages (a Mailpit search on its own values); or a 404 inside `list()` is skipped **only** for a message shown not to be the file's own. A 404-skip on its own stays refused.
3. **Mailpit's cap.** ci.yml pins `axllent/mailpit:v1.33.0` with no setting for the number of stored messages, so Mailpit's default limit, which prunes the oldest messages, applies. Without clears the inbox grows through the whole Stage 11 run. The PR body states the pinned version's default limit and the peak message count in one full Stages 1 to 11b run (a one-off count line), with the margin, or explains why the design is not affected by pruning. **A change to ci.yml or compose comes to master first.**
4. No retry, budget, timeout or skip change, and every assertion is kept.

**Proof.** **P1 and P2** as in DL-305 (5): the 404 signature does not recur on the fix PR's run of record, and not on the first `master` push run after the squash. **P3 (new, DL-325 (F)):** QA reads the Stage 11 log of the **next 10 CI runs after the squash, on any branch** (`gh run view --log-failed` or the job log, grep "Mailpit answered"); any recurrence **reopens DEF-064 the same day**. QA's mechanism reading at the squash: `git grep` shows no remaining path that removes a message another file can GET (the three `clear()` calls, any `DELETE` of `/api/v1/message*`, and the cap of the point above). P3 is needed because at about 1 in 8 runs, two green runs pass about 3 times in 4 with no fix (DL-296 (2)).
