## 1. DEF-137: below 1024 px the tree comes BEFORE the stages

**Ruling: the design wins. The tree is above the row heading, the box and the stages, never after the six stage cards.** QLT-789-04's "stages first below 1024 px" is withdrawn.

Why, from the design:

- The mock-up is one grid, `.ws`, with the tree (`.ws-tree`) first and the row detail (`.ws-form`) second. Nothing in `screens.css` or the ux-spec moves the tree after the stages at any width. At 768 px it is a column **left of** the detail; at 360 px it is a slide-over drawer off to the left (`.ws-tree` is `position: fixed`, `translateX(-102%)`), so it is not on the page at all until opened.
- The ux-spec (SCR-07 "Responsive") says "Tablet: accordion, all open. Phone: accordion, only stage 1 open": that is about the **stages**, and it says nothing that puts the tree last.
- The silence you found is real in one place: the mock-up's SCR-07 draws no button that opens the phone drawer (only the drawer's own Close). So the phone design is not fully drawn, and the build has to choose.

**The build's rule below 1024 px (same as the accepted SCR-06 layout, `estimate-review.tsx`):**

1. The tree is a foldable `details` panel, **placed before** the `COST DETAILS FOR ONE ROW` heading (after the page head, with `Back to the estimate` still beside the title or under it as built). At 360 and 768 px alike.
2. It is **closed by default** on this screen, with the summary `Parts tree` and the open row after it, `Parts tree · 1.1.1 Corner gusset` (the words SCR-06 uses). The Lead arrived to read one row's stages, so the stages are in view at once; opening the panel lists the rows, and pressing a row opens that row's cost details (a link, as on SCR-06). This is the one difference from SCR-06, where the tree is open by default: there the tree is the main way to pick a row, here the row is already picked.
3. Keyboard and screen reader: the summary is the control (`details`, no script); the rows are links in tree order; the open row has `aria-current="true"`. The whole summary line is the target, at least 44 px on touch.
4. The tablet's open two-column layout of the mock-up (tree left, detail right) is **not** reproduced below 1024 px; the foldable panel is the accepted answer for 360 and 768 px (ux-spec "SCR-06 parts tree", applied here for the same reason).
5. From 1024 px the tree is the left column (part 2).

In code this is the order of the two blocks and the `open` attribute: one class and a default.

## 2. DEF-136: the designed layout at 1366 px

**The mock-up's layout is two columns, not three.** The tree is the left column; the right column is **one card holding, from top to bottom: the label and title, the box, then the six stage cards**, each stage full width of that card. The build today draws three columns (tree, box, stages) and squeezes the stages into about 360 px.

### 2.1 Numbers (from `screens.css`, the grid `.ws`; the page is `max-width: 1320px`, padding 32 px, gap 24 px)

| Item | Value at 1366 px |
|---|---|
| Side menu | 248 px (as every screen) |
| Page content width | 1366 − 248 − 2 × 32 = **1054 px** |
| Grid columns | `var(--tree-w)` **320 px** (the SCR-05 and SCR-06 token; the mock-up's inline `--tree-w: 328px` on this one screen is withdrawn for the one number every tree uses), then `minmax(0, 1fr)` = **710 px**. The third column, the drawing region, is 0 px and is **not drawn** on SCR-07 |
| Gap | `--s-5` 24 px from 1280 px, `--s-4` 16 px from 1024 to 1279 px |
| Tree card | Sticky below the top bar (`top: topbar-h + 16 px`), as high as the window leaves it, with its own scroll; no resize handle (the review tree is not resizable, PRD ED-AC-15) |
| Right column | One card, `card-body` padding 16 px; its content stacked with 16 px between blocks |
| Stage cards | Each **710 px minus the card's padding**, about 678 px: wide enough for a formula and its substituted formula on one line each in most cases |

From 1024 to 1279 px the same two columns apply, with the 16 px gap; the stages are then about 590 to 650 px wide.

### 2.2 The right column, top to bottom (no side-by-side)

1. `COST DETAILS FOR ONE ROW` (label, capitals, muted) and the title `1.1.1 · Corner gusset` (the number in mono), as built.
2. **The box** `This row, on screen and in the Excel row` (BG, the count sentence, dollars and euros, the rounding sentence), **full width of the column, above the stages**. It is not beside them.
3. The six stage cards, in order, as DEF-114 and the earlier rulings say (all open at 1366 px).

### 2.3 What each tree row shows (the review tree of SCR-06, with the second line changed)

Use the **same card and rows as SCR-06's tree** (`ReviewTree`, `PartsTreeList`), with these differences:

- **First line:** arrow cell, kind tile (24 px), the Sl. No in mono 12 px, **a gap of `--s-2` (8 px) between the Sl. No and the name** (this is the fault: the build runs them together, `1Control cabinet assembly`), then the name, which wraps and is never cut.
- **Second line, right-aligned under the name** (the mock-up's `.tree-fig`, `grid-column: 3 / -1`, `justify-content: flex-end`): the count for the whole order, muted, then the row's own BG in bold with two decimals and no currency sign: `2 nos  3,583.99`. While the figures are cleared the figure reads `Cleared` in italic with the count kept; while nothing is calculated it is a dash. No dollars and euros line, no `View cost details` link on this screen: the row **is** the link to its own cost details.
- **The open row** (`aria-current="true"`): the SCR-05 look, `--surface-2` fill, a 4 px `--primary` bar at its start, the name in bold. The build's pink chip is withdrawn.
- **Not drawn:** the status ticks of the mock-up (every row of a calculated estimate is complete, and SCR-06's tree has none), the resize handle, any toolbar.
- Head `Parts tree` with `12 rows` at the right; foot: the kinds legend, and the sentence `Each figure is that row's own BG. The count for the whole order (QTY per Assy) is shown beside it and is already included. The estimate total adds every row's BG.` once, as SCR-06 words it.
