## Steps to Reproduce (lane 2's; not yet run by QA)
1. On the Lead's review page with the editable island (#811), add a part: the new row opens and the island rewrites `?row=` on the guard's extra history entry.

3. Press Back: the guard asks.
4. Press Back again.
5. Choose 'Leave without saving'.

## Expected / Actual
**Expected:** the person leaves the page, as on any other path. **Actual:** the page does not leave: `history.go(-2)` lands on the same estimate page (`?row=1.2`) instead of the queue. **Data loss:** none; no text is lost, the person stays on the page.

## Suspected Area (QA's code read, not a finding of cause)
`src/lib/estimates/leave-guard.ts` lines 153 to 166: after the guard's Back the leave goes `history.go(-2)`, which assumes the history is [the page before, the page's own entry, the guard's extra entry]. An add on the island writes a new `?row=` address into the history, so two steps back reach the page's own earlier address, not the page before it. **CORRECTED by DL-476 note (6): the cause is the guard's own click path (`leave-guard.ts:104`, `:135-146`: a same-page link with another `?row=` is treated as leaving; while the entry is armed even a clean click runs `router.replace` onto it, leaving two estimate-page entries), not the island's `replaceState`.**
